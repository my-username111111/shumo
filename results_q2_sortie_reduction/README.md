# 第二问：在时间和能耗附近减少架次（2026-09-24）

## 结论

以 `results_q2_time/frontier_24/weighted_plan.json` 为参照，将“另外两个维度”具体设为最晚返航时间和总能耗。此轮找到一份 **23 架次**的独立核验方案，但没有找到同时不超过参照时间 **6073.208 s** 和能耗 **69.154516 kWh** 的 23 架次方案。未找到只代表下述邻域搜索的结果，**不构成全局不可行证明**。

| 方案 | 架次 | 最晚返航 / s | 总能耗 / kWh | 加权交付时间 | 软延误 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 24 架次参照 | 24 | 6073.208 | 69.154516 | 2500844.903 | 0 |
| 原有 23 架次快方案 | 23 | 6112.317 | 69.307237 | 2497000.609 | 0 |
| **本轮改进的 23 架次快方案** | **23** | **6112.317** | **69.291327** | **2496472.609** | **0** |
| 原有 23 架次低能耗方案 | 23 | 6139.208 | 68.610770 | 2613002.059 | 0 |

本轮改进的 23 架次方案见 [same_zone_swaps_23_cap6930_best_plan.json](same_zone_swaps_23_cap6930_best_plan.json)。与 24 架次参照相比，少 1 架次，最晚返航增加 39.109 s（0.644%），能耗增加 0.136811 kWh（0.198%），加权交付时间减少 4372.294（0.175%）。与原有 23 架次快方案相比，最晚返航不变，能耗减少 0.015910 kWh，加权交付时间减少 528.000。

具体改动：交换原 23 架次方案中两条首发 S001 的 C 型航线上的 `S001-WAT-08` 与 `S001-HYG-02`。两个航线的箱数和各自运行时间不变，载重重新分配后降低能耗。程序重新安排实体无人机、电池和起飞时间，再由 `verify_q2` 独立复核。结果覆盖 80 个货箱，31 个硬时限货箱均满足约束，软延误为 0。

## 已检查的邻域

1. 从原有 23 架次快方案把一箱从 C 型航线转移给现有 A/B 航线：仅发现 6 个通过单航线物理与相对时限筛选的变体，全部未能同时满足时间和能耗参照上限。
2. 从 24 架次参照方案删除两箱航线 `T016`，将两箱分配给不同的 A/B 航线：8 个物理候选经精确资源排程均不可行。
3. 原有 23 架次快方案的 A/B 航线之间，筛选 107 个单箱搬运且航线能耗下界改善至少 0.1 kWh 的候选：在 `6114` 秒保守整数时间上限和参照能耗上限下均不可行。放宽能耗后，一些候选可维持 6112.317 s，但总能耗仍高于参照值。
4. 原有 23 架次快方案的同服务区跨航线换箱：6 个固定机型能耗改善候选在参照能耗上限下均不可行；放宽至 69.30 kWh 后得到本轮改进方案。
5. 从原有 23 架次低能耗方案将一箱从 C 型航线移至 A/B 航线：28 个物理候选在 6114 秒保守整数时间上限和参照能耗上限下均不可行。

这些试验使用原题给定的 A/B/C 型机、8 架实体运输机、按机型共享电池、逐箱交付时限、DEM 航段时间和能耗、20% 返航电量下限。候选航线先经过 `Dispatch.evaluate`，再由 `q2_exact_schedule.solve_case` 的 CP-SAT 模型排程；输出计划必须通过 `verify_q2`。CP-SAT 的 `INFEASIBLE` 仅针对当前固定货箱分组、航点顺序及给定上限。

## 复现

在仓库根目录，使用安装了 `ortools` 的 Python 环境运行：

```powershell
.\.venv\Scripts\python.exe results_q2_sortie_reduction\probe_t016.py
.\.venv\Scripts\python.exe results_q2_sortie_reduction\probe_23_relocation.py
.\.venv\Scripts\python.exe results_q2_sortie_reduction\probe_23_same_zone_swaps.py
.\.venv\Scripts\python.exe results_q2_sortie_reduction\probe_23_same_zone_swaps.py --energy-cap 69.30 --case main --name same_zone_swaps_23_cap6930
.\.venv\Scripts\python.exe results_q2_sortie_reduction\probe_low_energy_23.py
```

原有 23 架次快方案固定货箱分组时，以 6114 秒为保守整数上限最小化能耗，得到的最优排程能耗仍为 69.307237 kWh；因此若要达到 24 架次参照能耗，必须调整货箱分组或航线。下一步优先探索多箱连锁转移，使一条 B 型航线降载后可改由 A 型执行，释放 B 型资源；单箱直接转移不足以实现这一步。
