# 第三、四问：固定任务结构的连续时间优化

本轮在已有已认证第三问方案上增加 `optimize_q3_timing.py`。它固定80箱的组批与访问顺序、23条运输航线及机型、运输机和电池的接续次序、3个中继的空间位置及原通信区间的覆盖义务，用连续时间线性规划重排任务开始和中继服务时段。再由原有独立物理/DEM通信回放和精确第四问程序重新认证。**线性规划的最优性仅限于这些已固定的决策；不宣称第三、四问联合全局最优。**

实际重算的通信归属可能因中继服务区间重叠发生微小变化，第四问始终以**重认证后的实际关系**重建任务块。每份 `timing_lp_report.json` 记录归属变化的时长；全部新方案均已通过Q3、Q4独立回放。

## 2. 第四问实际结果

每份新Q3冻结后独立枚举全部合法两组/三组方案，并验证任务块、区间峰值、匹配下界、资源接续链及库存编号。本轮五个新方案的任务块仍为 `{S001}`、13区大块和 `{S011}`；因此两组仍只有 P1/P2/P3，三组只有 P4。1 dB方案推荐P3需要资源向量（A/B/C机、A/B/C电池、中继机、能源组件）`(4,3,2,6,5,4,2,3)`，比库存多1架B型机和1组B型电池。**时间重排未消除这2件缺口，也未突破13区任务块造成的工作量失衡。**

已有“重组B型瓶颈”的第三问备选经本轮时间优化后，P3最低需求为`(4,2,2,6,3,4,2,3)`，逐类型库存缺口为0；但它仅是**0 dB附加损耗**情景，存在32104.922加权软延误，最小硬时限余量只有7.154秒。它展示“库存自足”的代价，不能和1 dB、零软延误的主方案混称为同口径改进。相对该备选的上一版，本轮减少软延误41.308、加权交付462.292、完工2.066秒和能耗0.019310 kWh；最低接续从5.099796秒降为5.000100秒，仍满足明确的5秒条件。

## 3. 数学模型与审计范围

线性规划变量为每条运输任务起始时刻、每条中继起飞和服务结束时刻、联合完工时刻。原同一实物资源上相邻任务保持次序；运输机与电池分别以返航、充满为释放时刻，中继机以周转完成为释放时刻，均额外要求指定接续缓冲。将原实际中继通信区间随运输轨迹平移，要求该区间仍落在原中继的服务窗口中，并保留0.0001秒数值容差。中继服务时长受电池返航余量限制。全部医疗和首批硬时限约束保留；主情景还强制其余箱零软延误，库存自足备选则先最小化软延误。

目标按确定的字典序求解：时效优先为软延误（若开放）→加权交付→完工→中继服务时间；节能优先为中继服务时间→加权交付→完工，并可设交付/完工上限。运输能源在本局部模型中固定，因而最小中继服务时间等价于最小总能耗。OR-Tools GLOP返回各阶段 `OPTIMAL`；这只证明固定航线、机型、资源次序、选址和原中继覆盖义务后的连续时间子问题最优。每个最终计划再用独立几何内核验证DEM遮挡、全轨迹通信、能量/SOC、时限、资源间隔，并由精确Q4程序重算分区。

通信再认证可能改变约0.367秒的原中继归属；节能优先5秒方案改变约715.566秒。所有变化都在保存的 `q3_plan.json` 实际区间中，Q4没有继续使用旧任务块。余量下界是保守证书，不能解释成真实信号瞬时精确最小值；1 dB附加损耗也不覆盖任意天气、设备故障或带宽限制。

## 4. 文件与复算

- `selection/<方案>/q3_plan.json`：完整逐箱、逐架次、逐相位及连续通信认证计划。
- `selection/<方案>/timing_lp_report.json`：输入、LP阶段、重认证关系变化和Q4摘要。
- `selection/<方案>/q4/`：全部分区、资源需求与缺口、独立最优性证书、实物编号和验收报告。
- `comparison.csv`、`manifest.json`：统一口径指标、SHA256及代码指纹。
- `seeds/buffer5_cp.json`：节能优先分支用到的5秒CP候选；另附搜索配置和运行记录。它是**有限候选**，并非第三问全局最优证据。

在 `shumo_sync` 目录运行：

```powershell
.\.venv\Scripts\python.exe deliver_q3_q4_timing.py
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

交付程序会重新求解五个方案、复算每个固定Q3的完整第四问、写出CSV并核验所有计划。它不会修改仓库默认主方案或既有结果目录。

后续最值得投入的是**改变Q3任务绑定结构**：在可接受的时效与1 dB通信条件下，尝试将13区大任务块拆小或重组S011货箱，才可能从根本上改善第四问均衡与B型库存缺口；任何新Q3都必须重新跑同一套连续通信和固定输入Q4验收。
