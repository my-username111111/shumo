# 山区洪涝无人机运输与通信协同优化求解代码

本目录优先读取上一级 `D题/数据` 文件夹中的原始 Excel 和 30 米 DEM，若不存在则读取上一级 `数据` 文件夹；不修改原始附件。Git 仓库不包含题目原始数据及生成的 `results` 文件夹。运行 `run.py` 后，四问的结果、逐箱交付记录、资源时序和独立复算报告写入 `results`。第一问与公共运输核验的最新实现、结果和后续路线见 `交付说明_v4.md`；第二问的最新方案见 `Q2_交付说明.md`，对标复盘见 `Q2_对标复盘.md`，下一轮文献与方法调研见 `Q2_新方法调研_2026-09-23.md`。`v3.md` 保留升级前的完整审查清单，`交付说明_v2.md` 和 `交付说明.md` 分别保留 v2、v1 阶段记录。

四问的不足、改进原因、具体实施方式与验收标准见 [v3 四问审查与改进方案](v3.md)。该文档保留审查时的设计路线；第一问与第二问的已实施改动分别见 `交付说明_v4.md` 和 `Q2_交付说明.md`。

## 运行

需要 Python 3.10 及以上、NumPy、openpyxl、Pillow。若本机 Python 尚未安装依赖，可先执行：

```powershell
python -m pip install -r .\requirements.txt
python .\run.py
```

只计算和核验第二问，可执行 `python run.py --only-q2`，结果单独写入 `results_q2`；其中 `q2_result_template.xlsx` 已填写原题模板的两个 Q2 工作表。第二问的目标、九套方案及与第三问的衔接见 `Q2_交付说明.md`，可直接用于论文的文字见 `第二问_论文正文.md`，与外部截图的历史比较见 `Q2_对标复盘.md`。

另有固定路线 CP-SAT 排程实验，见 [Q2_精确资源排程实验.md](Q2_精确资源排程实验.md)。该实验的 28 架次方案以 2,662,962.480 的加权交付值优于路线修复流程的 22 架次主方案，但能耗较高；完整结果、逐箱核验和填好的 Q2 模板在 `results_q2_refined`。两套流程分别保存、分别复算，比较范围见 `Q2_交付说明.md`。该实验使用 `q2_exact_schedule.py` 和 `build_q2_refined.py`，额外依赖见 `requirements-q2-exact.txt`。探索依据与方法边界见 `Q2_新方法调研_2026-09-23.md`。

八套第二问方案的硬时限、逐箱时效、资源占用及 A/B/C 机型配比见 [Q2_多维对比与机型选择.md](Q2_多维对比与机型选择.md)；执行 `python q2_multiaxis_compare.py` 可重新生成 `results_q2_refined/q2_multiaxis_comparison.csv` 和 `q2_fleet_mix.csv`。

外部第二问截图的汇总数值、可比性边界及现有 52 条路线的集合重组试验见 [Q2_外部截图对标与路线搜索方向.md](Q2_外部截图对标与路线搜索方向.md)；`q2_route_pool_probe.py` 仅用于找有限路线池的潜在架次，不把未排程的集合覆盖当成第二问可行解。

第二问进一步采用箱组路线合并与精确资源排程，得到经独立复算的 24、23、22、21 架次零软延误方案。24 架次快速节能方案在加权交付、完工、能耗及架次上严格支配原 25 架次节能方案；23 架次均衡方案接近原 28 架次主方案的加权交付时刻，同时明显降低能耗。该阶段方法与结果见 [Q2_继续优化_路线合并与多目标对比.md](Q2_继续优化_路线合并与多目标对比.md)，`results_q2_extended` 含完整方案 JSON、独立核验、A/B/C 机型配比和 Q2 结果模板。

第二问最新箱级重分配突破了完整路线两两合并的局部障碍，得到 20 架次与三种 19 架次零软延误方案；19 架次交付优先方案为 65.606599 kWh、最晚返航 8,466.170 秒、加权交付 2,958,556.179。新结果、12 套方案比较、4 份新增 Q2 模板、有限路线池 18 架次试验及方法边界见 [Q2_继续探索_v2_19架次与路线池.md](Q2_继续探索_v2_19架次与路线池.md)。

`--no-sensitivity` 跳过问题一的返航余量敏感性；`--no-merge` 保留问题二初始单服务区架次；`--no-coordination` 使用固定运输初值求中继，便于作消融对照；`--no-figures` 跳过绘图。默认执行完整流程。可以用 `--output 绝对目录` 指定结果目录。`--q3-seed` 选择第三问的运输初值，默认是已验证可接续的 `energy_guarded` 方案。`--promotion-trials`、`--coordination-rounds`、`--coordination-trials` 控制联合搜索预算；结果固定随机种子 2026，可复现。

第一问的严格升级版单独运行，不触发第二至四问搜索：

```powershell
python .\run_q1.py --data-dir "题目D题\数据" --output .\results_q1
python -m unittest discover -s .\tests -v
```

它穷尽 18 至 80 架次的全局时间—能耗 Pareto 前沿，逐候选求返航余量临界点，并用不调用主计算函数的栅格、物理量和逐箱位掩码算法交叉复算。主要结论与精度边界见 `results_q1/第一问升级报告.md`，机器可读证书见同目录 JSON/CSV。第一问的“时间”是各架次累计作业时间，不是第二问带实体机、电池并行调度后的完工时间。

## 文件与算法

| 文件 | 用途 |
| --- | --- |
| `model.py` | 读取附件；DEM 栅格穿越、航段净空、时间和能耗、电池充电、双向链路预算与 DSM 遮挡。四问共用。 |
| `q1.py` | 二分求 15×3 最大安全载荷；逐服务区枚举可行货箱集合并用精确动态规划求字典序最优组批；支持分别以能耗和时间为第二目标。 |
| `q1_frontier.py` | 按同质货箱计数的独立精确动态规划；保留全部机型/箱组，求各架次数及跨架次数全局 Pareto 前沿、总能耗预算解和所有返航余量临界事件。 |
| `q1_reference.py` | 逐实际箱号位掩码的参考算法，独立核对全局 Pareto 点和每个精确架次数可达到的最大统一返航余量。 |
| `transport_check.py` | 独立运输回放器；采用线段—栅格矩形相交，不调用主核的航段、时间和能耗函数。 |
| `run_q1.py` | 仅运行第一问并导出18架次证明、全局权衡、临界余量和独立交叉核验证书。 |
| `q2.py`、`q2_alns.py`、`q2_refinement.py` | 对硬时限与普通货箱按实际时间统一排序，显式分配实体运输机和同型共享电池；搜索合并、移箱、换箱、拆分、访问顺序和执行顺序。两阶段 ALNS 之后用增量能耗修复及资源时序搜索，合计输出九套可行方案。 |
| `q2_exact_schedule.py`、`build_q2_refined.py` | 在已有第二问箱组与访问顺序上，用 CP-SAT 联合排实体机、共享电池和起飞时刻，再经连续时间物理核验并导出新旧方案对照。 |
| `q2_multiaxis_compare.py` | 在同一物理与独立核验口径下，对比八套第二问方案的时效分布、硬时限余量、A/B/C 实体机启用数、架次和占用率。 |
| `q2_merge_search.py`、`q2_frontier_refine.py` | 枚举两架次箱组合并并做资源精确排程；在能耗与完工上限下进一步优化加权交付时刻。 |
| `build_q2_extended.py`、`q2_audit_20_branches.py` | 汇总新旧第二问方案、独立复核、导出结果模板，并记录有限路线池的 20 架次局部搜索范围。 |
| `q2_ejection_search.py`、`q2_three_to_two_search.py`、`q2_absorb_source.py` | 箱级 3→2 重分配：可拆原三条路线的货箱、枚举新的 B/C 箱组与访问顺序，再做实体机、电池和全时限精确排程。 |
| `q2_route_pool_probe.py` | 对已核验与候选路线做受限 exact-cover 重组，并将整套路线交给 CP-SAT 检查；有限池结果不作为全局最优性证明。 |
| `q3.py` | 从 DEM 内生成中继悬停候选；用链路预算筛选任务覆盖；允许把软时限架次插入较早的硬时限波次；安排两架中继机和能源组件的往返、建链与充电；对通信逐段采样复核。 |
| `coordination.py` | 问题三的通信反馈搜索：以问题二的运输解为基线，试算软时限架次提前插入、整箱移位、架次拆并、访问和执行顺序变化；每个候选重新运行运输资源调度和完整中继求解，仅保留可行且联合目标更好的解。 |
| `q4.py` | 根据多点运输和实际中继保障关系形成不可拆的服务区连通分量；穷举两组、三组分区并核算设备缺口与工作量平衡。 |
| `verify.py` | 重算所有架次的载荷、时间、能耗、SOC、硬时限、资源占用与通信；第二问额外核对设备编号、机型、逐箱来源、保存轨迹和目标汇总。 |
| `figures.py` | 绘制 DEM 背景航线图、运输与中继甘特图、两组和三组分区图。 |
| `run.py` | 串联计算并输出 JSON、CSV。 |

问题一在已定义的物理模型下为精确解。18 架次由逐服务区重量/体积下界与可行证书闭合；全局时间—能耗权衡枚举全部可行架次数，不使用加权和近似。问题二是独立的运输方案，默认以普通物资的加权软延误为第一目标；`results_q2` 路线修复流程的主方案为 22 架次、零软延误、67.606 kWh，另保留 24 架次较快方案和 22 架次最低能耗方案。`results_q2_refined` 的固定路线 CP-SAT 排程方案加权交付更早，属于另一套实验。问题三从问题二的限时节能备选方案启动通信联合搜索，因此两问的运输架次可以不同。问题二、三为可行方案搜索，不宣称全局最优。问题四对问题三形成的不可拆任务单元穷举全部 2 组和 3 组分区；同时输出“严格沿用原设备编号”和“保持任务时序、允许组内重新编号”的资源口径。

联合搜索的设计参考 Meng 等（2024）的自适应大邻域搜索思路、Rottondi 等（2021）的灾后多任务联合调度，以及 Yanmaz（2022）的任务轨迹与中继配置模块化方法。这里的算子、时间波次插入和物理校验均针对本题重新实现，并非复现论文数值。参考文献：

* Meng, S., Chen, Y., Li, D. *The multi-visit drone-assisted pickup and delivery problem with time windows*. European Journal of Operational Research 314(2), 2024. https://eprints.lancs.ac.uk/id/eprint/207820/
* Rottondi, C. et al. *Scheduling of Emergency Tasks for Multiservice UAVs in Post-Disaster Scenarios*. Computer Networks, 2021. https://arxiv.org/abs/2010.10939
* Yanmaz, E. *Positioning aerial relays to maintain connectivity during drone team missions*. Ad Hoc Networks 128, 2022. https://doi.org/10.1016/j.adhoc.2022.102800

## 统一计算口径与显式假设

* 服务区起降作业海拔取节点表给出的地面海拔加 30 米，O01 取节点表地面海拔；航段最高地形从 DEM 读取。运输航段巡航海拔为沿线最高 DSM 加 50 米。中继悬停点可能高于这个高度，因此中继航段巡航海拔还须不低于两端点海拔。
* 题目给出载荷相关等效航程，却没有单独列出水平能耗和爬升能耗的完整计算式。本代码明确采用 `E_horizontal = E_use × distance / L(q)`，`E_climb = (empty_mass + q) × 9.81 × climb / (3.6×10^6 × climb_efficiency)`，单位为 kWh。下降不加独立能耗。论文应列明并讨论此假设的影响。
* 架次开始时刻包括工位准备和装箱；逐箱交付时刻取该服务区交接完成时刻；运输任务完成取最后一架返抵 O01；联合任务完成取运输与中继的最晚返抵时刻。
* 电池和中继能源组件初始为 100% SOC；每次使用后按附件两阶段模型充至 100% 才能再投入任务。不同资源允许并行充电。运输无人机未给出额外架次周转时间，下一架次自身准备时间已经计入；中继无人机使用附件给出的 300 秒周转时间。
* 通信按运输机与 G01 双向链路，或运输机与中继接入端及中继回传端与 G01 的两段双向链路判定。附件未给出同一中继的并发容量上限，程序允许它同时保障多架运输机，且逐架检查链路。
* 道路、水体和村镇点位用于解释地理场景；题目指定飞行航段为节点间水平直线，因此程序没有额外假定避水或沿道路飞行约束。

## 结果与核验

`results/summary.json` 给出四问指标。`q1.json` 至 `q4.json` 保留完整模型结果和资源时间；`q3.json` 的 `search.coordination` 记录原固定 Q2 基线、各候选可行性、最终改进值与选用的波次插入。同名 CSV 便于填入结果提交模板。`validation.json` 给出独立复算数量与通信采样检查。`q3_route_map.png`、`q3_resource_timeline.png` 和 `q4_partition_map.png` 可用于检查空间和时间安排；论文定稿前可按版式再绘制。

问题三的中继候选要求接入和回传链路至少有 2 dB 余量，通信缺口前后各预留 90 秒覆盖。覆盖计算采用时间采样，结果再以 2 秒和 1 秒步长分别复核。它是**数值可行性检查**；若论文要使用严格的“连续通信保证”表述，还需增加时间区间上的地形视线界限证明或保守的连续区间证书。最终逐秒复核的最小余量可能略低于候选点的 2 dB 门槛，因为沿航线的位置会变化；实际部署还应做链路参数扰动分析。

问题四默认展示“最小库存缺口”分区，同时在 `q4.json` 和 `q4_partition_resources.csv` 中保留工作量最均衡及限制额外资源后的折中分区。最小缺口方案可能明显失衡，因此论文中应并列展示，而非只报一个方案。
